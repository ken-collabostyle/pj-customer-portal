# kintoneアプリ「商品マスタ」

**定価取得（kintone REST API経由）は不使用（2026-09-11）**：ユーザーが業務支援チームと調整し、定価取得元を[ライセンス種類マスタ](ライセンス種類マスタ.md)（「月額単価」フィールドを新規追加）に変更する方針となったため、`.env`の`KINTONE_PRODUCT_MASTER_*`キーやプロキシAPI経由でのREST APIアクセスは行わない。

**一方、フォーム側の既存機能「新規追加商品名（`fidAddedProductName`）のlookup」は引き続き本アプリ（コラボフロー内の設定名「【検証用】商品マスタ」）を参照する（変更なし）**。2026-09-16、このlookup設定に「商品区分2」フィールドを追加し、`fidAddedProductCategory`パーツへ自動セットする設定が追加された（[実装メモ](../forms/requirements/【クラウド版】注文書兼利用申込書（月額：契約変更）_実装メモ.md)参照）。これにより、フェーズ1ステップeで保留していた「新規追加商品の区分判定」の突合キー問題が解消。ライセンス種類マスタへの追加アクセスは不要となった。

以下は経緯を残すための旧内容（定価取得元としての検討時の記載）。

オプション等を新規追加する場合の「定価」を取得するためのアプリ。[クラウド契約管理DB](クラウド契約管理DB.md)には定価情報が含まれないため、こちらを参照する想定だった（→上記の通り不使用に変更）。

取得方法：kintone REST API `GET /k/v1/records.json?app={KINTONE_PRODUCT_MASTER_APP_ID}&query=...`。認証情報は`.env`の`KINTONE_BASE_URL` / `KINTONE_PRODUCT_MASTER_APP_ID` / `KINTONE_PRODUCT_MASTER_API_TOKEN`を使用（実値はこのファイルに書かない）。

フィールドコードは`getFormFields` APIで取得した生レスポンス（[docs/kintone/json/商品マスタ_getFormFields.json](json/商品マスタ_getFormFields.json)、2026-09-02取得）を一次情報とする。**下表は2026-09-02にこの生JSONと突合し、以前の版に含まれていたフィールドコードの誤りを修正済み**（誤：`標準売価`→正：`標準単価`（ラベルが「標準売価」なので紛らわしいが、コードは異なる）、誤：`月額・年額`→正：`月額年額`）。

## 未確認事項・今後のヒント（2026-09-02 生JSON突合で判明、2026-09-11解消）

- `ラジオボタン_0`（ラベル「単位」、選択肢：本／回／式）というフィールドが存在する。[フェーズ1ステップaの実施記録](../agent-records/2026-09-02_フェーズ1ステップa_インスタンス名UIとkintone連携_実装.md)で未解決課題として残した「明細の変更後商品単位（`fidChangedProductUnit`）のデータソース不明」に対し、`製品型番`（クラウド契約管理DB）と`文字列__1行_`（メーカー型番、本アプリ）を突合すればこのフィールドから単位を取得できる可能性がある、という案を出した。
- ~~**保留（2026-09-02）**：その後、クラウド契約管理DBと商品マスタは直接連携しておらず、間に「ライセンス種類マスタ」アプリを挟んでいることが判明。`製品型番`⇔`メーカー型番`の単純な突合が成立するかどうか自体が不確実なため、この案は業務支援チームとのkintoneアプリ構造検討が完了するまで保留とする（[全体計画](../plans/2026-08-24_顧客ポータルカスタマイズ全体計画.md)「商品マスタ関連の保留事項」参照）。~~
- **解消（2026-09-11）**：業務支援チームとの調整の結果、フォーム側の単位関連パーツ（`fidChangedProductUnit`・`fidAddedProductUnit`）自体が削除された。データソースを探す前提そのものがなくなったため、本件は保留ではなく解消として扱う。
