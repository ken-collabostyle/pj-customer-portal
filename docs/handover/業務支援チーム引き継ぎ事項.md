## 1. 区分「オプション（ライセンスキー不要」の閉じ括弧の欠落

- 登録日：2026-11-18
- ステータス：open（開発時点では考慮しない。ユーザー判断、2026-11-18）

### 内容

クラウド契約管理DBの`区分`の選択肢が、閉じ括弧のない「オプション（ライセンスキー不要」になっている。ライセンス種類マスタ（アプリID: 80）の`区分`と、コード（[contract-change-shared-logic.ts](../../src/forms/contract-change-shared-logic.ts)の`OPTION_CATEGORIES`）は、閉じ括弧のある「オプション（ライセンスキー不要）」になっている。

| 場所 | 値 |
|---|---|
| クラウド契約管理DB（73）の`区分` | オプション（ライセンスキー不要 |
| ライセンス種類マスタ（80）の`区分` | オプション（ライセンスキー不要） |
| コード（`OPTION_CATEGORIES`） | オプション（ライセンスキー不要） |
| 商品マスタ（78）の`商品区分2` | 文字列フィールドのため選択肢の定義なし。入力されている表記は未確認 |

### 影響

- コードの比較は完全一致のため、契約DBの既存行にこの区分があると、オプションのユーザー数整合性チェックの対象外になる。
- 2026-11-18時点で、契約DBにこの区分のレコードは0件のため、実害は出ていない。
- 新規追加行の区分は商品マスタの`商品区分2`の値次第。

### 本番以降に必要な対応（いずれか）

- A. 契約DBの選択肢を、閉じ括弧ありに修正する（kintone側の修正。コード変更は不要）。修正後、既存レコードの値も更新する。
- B. 開発側でコードの比較を、閉じ括弧の有無の両方を許容するように変更する。

## 2. テスト環境ライセンスの区分変更の本番反映順序

- 登録日：2026-11-20
- ステータス：open（本番反映時に対応）

### 内容

2026-11-18に、テスト環境ライセンスの判別を、商品コード・検索IDから、区分=「テスト環境」へ変更した（月額・年額共通。[contract-change-shared-logic.ts](../../src/forms/contract-change-shared-logic.ts)）。この変更はkintoneのデータが前提のため、**本番では、kintoneの反映を先に行い、JSのアップロードを後にする**必要がある。

### 本番で必要な作業（この順序）

1. クラウド契約管理DB（73）の`区分`に、選択肢「テスト環境」を追加する（表記は全角で、3アプリとも「テスト環境」に一致させる）。
2. 契約DBのテスト環境ライセンスのレコード（製品型番`CCTLST0000`系）の`区分`を、「オプション」から「テスト環境」へ変更する。検証環境では141件。
3. 商品マスタ（78）の、テスト環境ライセンスの`商品区分2`（フィールドコード`文字列__1行__5`）を「テスト環境」にする。
4. ライセンス種類マスタ（80）の`区分`を、「テスト環境」にする（コードは参照していないが、運用を揃える）。
5. 上記が済んでから、月額・年額のJS（`monthly-contract-change.js`、`annual-contract-change.js`）を本番フォームへアップロードする。

### 影響（順序を守らなかった場合）

- JSを先に反映すると、既存のテスト環境ライセンス行がオプション扱いのままになる。ベースのユーザー数と数量が合わないため、何も変更しなくても、オプションのユーザー数整合性チェックでブロックされ、申請できない（2026-11-20に検証環境で確認）。
- 商品マスタの`商品区分2`が空だと、テスト環境ライセンスを追加しても区分が空になり、URL希望①〜③の必須チェック（★1）が発動しない。

## 3. 新規追加商品名の商品検索（月額・年額フォーム）の本番移行

- 登録日：2026-11-20
- ステータス：open（本番反映時に対応）

### 内容

新規追加商品名（`fidAddedProductName`）を、lookupから、テキストパーツ＋虫眼鏡＋検索ダイアログ（プロキシAPI経由で商品マスタを検索）に置き換えた（2026-11-19）。本番には、次の作業が必要。

### 本番で必要な作業

1. **フォームのパーツ変更**：月額・年額フォームの`fidAddedProductName`を、lookupからテキストパーツに変更する。商品コード・単価・区分・按分月数（年額）のlookup設定は、JSがセットするため不要になる。
2. **プロキシAPIの作成（2件。コラボフォームのプロキシ設定はフォーム単位のため別名が必要）**
   - 月額版：`kintone-product-master`
   - 年額版：`kintone-product-master-annual`
   - 設定：GET、`/k/v1/records.json`、クエリパラメーターは`app=<本番の商品マスタのアプリID>`のみ、ヘッダー`X-Cybozu-API-Token`に本番の商品マスタ用トークン。**`query`は管理者側に設定しない**（管理者設定が優先され、JSから渡す検索条件が上書きできなくなる）。
3. **商品マスタ（本番）のデータ**：「商品名_マイページ用」と「商品区分2」が入力されていること。空だと、ダイアログに商品名が出ず、区分も空になる（区分に依存するチェックが働かない）。
4. 作業2の詳細設定は[kintone/README.md](../kintone/README.md)の「商品マスタ検索用プロキシ」を参照。

### 影響（作業が漏れた場合）

- プロキシが未作成・設定誤りだと、ダイアログに商品が出ず、追加商品を選べない。
- 商品名・区分が未入力だと、警告メッセージの商品名が空になり、ユーザー数整合性チェックや★1が働かない。
