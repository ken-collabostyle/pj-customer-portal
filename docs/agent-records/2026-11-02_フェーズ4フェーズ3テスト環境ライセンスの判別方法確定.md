# フェーズ4 フェーズ3 テスト環境ライセンスの判別方法の確定

- 日付: 2026-11-02
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

フェーズ3の保留項目（テスト環境ライセンス・コラボフォームの条件付き必須、同月内の減数不可）の詳細を整理した結果、いずれも判別方法・データソースが未確定であることを確認した。このうち、テスト環境ライセンスの判別方法について、ユーザーが回答した。

## 確認結果（Reasoning）

ユーザーからの共有：

- 新規追加時のテスト環境ライセンスは、lookupで商品コードがセットされる（`fidAddedProductCode`）ため、この商品コードを使って判別する。
- テスト環境ライセンスは、商品コードに「`CCTLST0000`」が含まれるもの。

## 反映内容（Acting）

- [フェーズ4計画](../plans/2026-09-25_フェーズ4_年額契約変更カスタマイズ計画.md)：フェーズ3の項目を「テスト環境ライセンス（★1）：判別方法が確定」と「コラボフォーム（★2・★3）：保留」に分け、更新履歴に追記
- [年額版実装メモ](../forms/requirements/【クラウド版】注文書兼利用申込書（年額：契約変更）_実装メモ.md)：★1の判別方法の確定を追記

コード変更はなし。

## 得られた知見・製品への示唆

新規追加商品の判別には、既存のlookupでセットされる商品コード（`fidAddedProductCode`）がそのまま使えるため、コラボフロー側のパーツ追加は不要。

## 未解決課題・申し送り事項

- ★1の必須となる項目の範囲：**確定（2026-11-02）**。`fidTestEnvUrlFirstChoice`・`fidTestEnvUrlSecondChoice`・`fidTestEnvUrlThirdChoice`（テスト環境のURL希望①〜③）の3つ。お試し環境のURLは対象外
- 必須化の実現方式：コラボフォームのJS APIにはパーツの`required`を動的に切り替える手段が見当たらないため、確認・送信時に未入力を検出して申請をブロックする方式（他ステップと同じ）でよいか、未確認
- ★2・★3（コラボフォーム）：新規追加商品・既存契約がコラボフォームかの判別方法、現在契約中のサブドメインのkintone取得元、「契約済み」の場合の必須化の意味が未確認
- 同月内の減数不可：「別途ユーザー追加」の判定データソースが未確認
- ★1の詳細計画を作成済み（[ステップ3-1計画](../plans/2026-11-02_フェーズ4ステップ3-1_テスト環境ライセンス申込み時のURL希望必須チェック.md)、承認待ち）
