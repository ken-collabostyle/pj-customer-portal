# フェーズ4 ステップa 年額版プロキシ名対応

- 日付: 2026-10-02
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

[ステップa実装](2026-09-28_フェーズ4ステップa_年額版インスタンス名UIとkintone連携_実装.md)をユーザーが検証環境にアップロードし実機確認した結果、プロキシAPIエンドポイント名に関する不具合が判明したため対応する。

## 調査内容（Reasoning）

ユーザー報告により、コラボフォームのプロキシAPI設定がフォーム単位であるため、月額版と年額版で同じエンドポイント名`kintone-contract-db`を共有できず、年額版では別名（`kintone-contract-db-annual`）のエンドポイントが必要であることが判明した。接続先kintoneアプリ・クエリ条件自体は月額版と同一（クラウド契約管理DB、アプリID: 73）であり、エンドポイント名のみの相違。

## 実施内容（Acting）

1. `src/forms/annual-contract-change.ts`の`KINTONE_CONTRACT_DB_ENDPOINT`を`"kintone-contract-db"`から`"kintone-contract-db-annual"`に変更
2. [docs/kintone/README.md](../kintone/README.md)に「エンドポイント1-b：`kintone-contract-db-annual`」を追加し、フォーム単位でエンドポイントが必要という制約を明記
3. [ステップa計画](../plans/2026-09-28_フェーズ4ステップa_年額版インスタンス名UIとkintone連携.md)に実機確認対応の経緯を追記

## 結果・観察（Observation）

`npm run lint` / `npm run typecheck` / `npm test`（58件）/ `npm run build`すべて再確認し通過した。

## 得られた知見・製品への示唆

コラボフォームのプロキシAPI設定が**フォーム単位**であり、同一kintoneアプリ・同一クエリ条件であってもフォームごとにエンドポイントを分けて作成する必要がある点は、今後フォームが増えた際にも同様に発生しうる制約。[docs/kintone/README.md](../kintone/README.md)に記録済みのため、次にクラウド契約管理DBへアクセスするフォーム（解約届等）を実装する際はこの制約を踏まえてプロキシAPI設定を計画する。
