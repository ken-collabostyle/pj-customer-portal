# フェーズ1ステップc：オプション新規追加時の現契約数デフォルト値セットは対応不要と判断

- 日付: 2026-09-10
- 担当: Claude（ken-collabostyleの指示のもと）

## 背景・目的

[詳細計画](../plans/2026-09-02_フェーズ1ステップc_オプション新規追加時の現契約数デフォルト値.md)（承認済み）の実装着手前に、ユーザーから「『現契約数』パーツは現状存在しないのでは。この処理自体が不要なのでは」との指摘を受けた。実装前に事実確認を行った。

## 調査内容（Reasoning）

- パーツ構造JSON（[docs/forms/json/【クラウド版】注文書兼利用申込書（月額：契約変更）.json:304-314](../forms/json/【クラウド版】注文書兼利用申込書（月額：契約変更）.json#L304-L314)）を確認したところ、`fidCurrentProductQuantity`（表示名「現商品契約数」、`number_v2`型）パーツ自体は実在し、テーブルの列定義にも含まれていた
- ただしJSONスナップショットは2026-08-25〜09-02頃取得のもので、現行フォームと乖離している可能性があるため、ユーザーに現状を確認
- ユーザー回答：パーツ自体は存在するが、①「変更後契約数を入力してください」セクションの列としてのみ配置されており、②「オプション等新規追加」セクション（`fidAddedProductName`の行）とは視覚的に無関係
- [実装メモ](../forms/requirements/【クラウド版】注文書兼利用申込書（月額：契約変更）_実装メモ.md)の当初の実装方針（`fidAddedProductName`選択時に同一行の`fidCurrentProductQuantity`へ0をセット）は、①・②が「同一テーブルの同一行」という構造上の事実のみに基づいており、実際の画面配置（①と②が視覚的に無関係なセクション）を踏まえていなかったことが判明
- ②側の新規追加行に対応する①側の`fidCurrentProductQuantity`へ「0」をセットすると、商品名が空欄のまま「現商品契約数＝0」という実体のない行が①セクションに表示されてしまい、かえって紛らわしいと判断
- `fidChangedProductPrice`の価格計算式（`fidChangedProductUnitPrice`×`fidChangedProductQuantity`）も`fidCurrentProductQuantity`を参照しないため、機能的な影響もないことを確認

## 得られた知見・製品への示唆

- 要求事項⇔パーツID突合表（実装メモ）は、パーツが「データ構造上存在する」ことと「画面上その文脈で意味を持つ位置に配置されている」ことを混同すると、実際には不要な実装を計画してしまうリスクがある。今回のケースでは「同一テーブルの同一行に共存する」という構造的事実だけでなく、画面上の視覚的な配置（どのセクションの一部として表示されるか）まで確認する必要があった
- 承認済みの計画であっても、実装着手前に前提の再確認を促すユーザーからの指摘は、無駄な実装（かつ紛らわしい表示を追加する実装）を未然に防いだ。計画承認後も実装直前に前提を再検証する価値があることを再確認できた
