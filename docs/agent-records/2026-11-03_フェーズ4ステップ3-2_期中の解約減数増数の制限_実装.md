# フェーズ4 ステップ3-2 期中の解約・減数・増数の制限

- 日付: 2026-11-03
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

業務支援チームの確認で、年額契約は期中の解約・減数・プランダウンができず、更新タイミングであれば可能と判明した（[2b-fの記録](2026-11-02_フェーズ4フェーズ2b-f減数解約禁止は不要と確定.md)）。ユーザーが「年額は期中の解約・減数ができないように制御する」と決定し、期中のフル年額商品の増数もNGと確認された。

## 調査内容（Reasoning）

変更適用月差分（2c-gで実装済み）を使い、差分1〜11を期中、差分0を更新タイミングと読み替える（ユーザー確認済み）。解約チェックボックスの無効化は`parts.enabled`が設定不可でDOM依存になるため、確認・送信時のブロック方式を採用した（警告は確認・送信時のみ、ユーザー確認済み）。差分12以上は「何かおかしいことが起こっている」ため、警告して申請不可とする（2c-gの`validateChangeApplyMonthDiff`に組み込む）。[詳細計画](../plans/2026-11-02_フェーズ4ステップ3-2_期中の解約減数の制限.md)でユーザー承認を得た。

## 実施内容（Acting）

`src/forms/annual-contract-change-logic.ts`
- `CHANGE_APPLY_MONTH_DIFF_ABNORMAL_THRESHOLD`（12）
- `findMidTermChanges`：期中（差分1〜11）の既存契約行の解約（`cancel`）・減数（`reduce`）・増数（`increase`）を返す。差分0・12以上・負、現商品契約数が空の行は対象外

`tests/forms/annual-contract-change-logic.test.ts`：`findMidTermChanges`のテストを追加。

`src/forms/annual-contract-change.ts`
- `validateMidTermChanges`：変更適用月差分を再算出し、期中の既存行の解約・減数・増数があれば警告して申請ブロック
- `validateChangeApplyMonthDiff`（2c-g）：差分12以上を新たにブロック（負のブロック・差分0の許可は変更なし）
- `form.confirm`/`form.submit`のチェーンに`validateMidTermChanges`を連結（`validateChangeApplyMonthDiff`の後、2c-hの前）

## 結果・観察（Observation）

`npm run lint` / `npm run typecheck` / `npm test`（115件、ステップ3-1・3-2で新規45件）/ `npm run build`をすべて実行し通過を確認した。2c-hで差分12以上を「防御的に差分0と同じ扱い」にしていた分岐は、本ステップで事実上到達しなくなった（防御的なコードとして残し、動作変更なし）。

## 得られた知見・製品への示唆

変更適用希望年月のデフォルトは当月（または翌月）で通常は期中になるため、既存契約行の解約・減数・増数を含む申請は、変更適用希望年月を契約期限の月にしない限り、申請できなくなる。運用への影響が大きい。

## 未解決課題・申し送り事項

ユーザーが検証環境で実機確認し、問題なしと確認した（2026-11-05）。これによりクローズした。確認した項目は[計画](../plans/2026-11-02_フェーズ4ステップ3-2_期中の解約減数の制限.md)「確認方法」の各項目、特に次の点の確認が必要。
- 期中：既存行の解約・減数・増数それぞれで「確認」押下時に警告が出ること。新規追加のみ（nヶ月分商品）なら進めること
- 更新タイミング（変更適用希望年月＝契約期限の月、差分0）：解約・減数・増数が許可され進めること
- 差分12以上の警告（再現が難しい場合はユニットテストでの確認）
- ステップa〜d・2c-g・2c-h・ステップ3-1の回帰確認
