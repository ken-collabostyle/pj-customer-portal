# フェーズ4 ステップ2c-h 新規追加時の「nヶ月分」商品妥当性チェック

- 日付: 2026-11-02
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

[フェーズ4計画](../plans/2026-09-25_フェーズ4_年額契約変更カスタマイズ計画.md)フェーズ2cのステップh。新規追加した商品の按分月数が変更適用月差分に対して妥当でない場合に、申請をブロックする。あわせて、更新タイミング（差分0）を許可するよう2c-gの検証を見直す。

## 調査内容（Reasoning）

コラボフロー側で`fidAddedProductProratedMonths`（追加商品按分月数、`number_v2`）が追加され、`fidAddedProductName`のlookupで値がセットされることをユーザーが実機確認済みであることを、更新後のパーツ構造JSONで確認した。これにより`kintone-product-master`プロキシは不要となった。ユーザー確認事項（按分月数5＝5ヶ月分、フル年額商品の期中追加は不正かつ確認ボタン押下時に警告、更新タイミング＝差分0は許可、差分0はフル年額のみ、差分12以上は運用上起こりえない、按分月数が空はチェック対象外）を反映した[詳細計画](../plans/2026-11-02_フェーズ4ステップ2c-h_新規追加時のnヶ月分商品妥当性チェック.md)を提示し、ユーザー承認を得た。

## 実施内容（Acting）

`src/forms/annual-contract-change-logic.ts`
- `findProratedMonthsMismatches(addedRows, changeApplyMonthDiff)`：差分1〜11（期中）は按分月数＝差分のnヶ月分商品のみ許可（フル年額は`fullYearOnMidTerm`、不一致は`monthsMismatch`）。差分0・12以上はフル年額のみ許可（nヶ月分は`partialOnRenewal`）。差分が負なら検証しない。商品未選択行・按分月数が空/数値でない/1〜12の整数でない行は対象外

`tests/forms/annual-contract-change-logic.test.ts`：上記関数のテスト12件を追加（期中、更新タイミング、差分12以上、差分負、対象外の行、複数行混在、文字列・数値の同一結果）。

`src/forms/annual-contract-change.ts`
- 定数（`fidAddedProductCode`・`fidAddedProductName`・`fidAddedProductProratedMonths`のパーツID）を追加
- `validateAddedProductProratedMonths`：明細各行から値を集め、変更適用月差分（再算出）とともに判定。不一致があれば最初の1件の種別に応じた文言で`alert()`＋`false`
- `validateChangeApplyMonthDiff`の見直し：`diff > 0`を`diff >= 0`に変更（差分0＝更新タイミングを許可、負のみブロック）。文言を「0未満」に変更
- `form.confirm`/`form.submit`のチェーンに`validateAddedProductProratedMonths`を連結

## 結果・観察（Observation）

`npm run lint` / `npm run typecheck` / `npm test`（92件、新規12件）/ `npm run build`（`dist/forms/annual-contract-change.js`再生成）をすべて実行し通過を確認した。

## 得られた知見・製品への示唆

- 按分月数の取得にkintoneプロキシを使わず、lookupでパーツにセットする方式（`fidAddedProductCategory`と同じ）にしたことで、プロキシ・突合キー・`.env`の設定が不要になった。
- 2c-gで「差分0以下は申請不可」としたが、更新タイミング（差分0）の運用が後から判明して見直しとなった。要求事項の運用実態（更新タイミングの扱い）は、実装前に網羅的に確認する価値がある。
- `parts.value`の型（文字列か数値か）は未確認のため、JS側は文字列・数値のどちらでも同じ結果になるよう実装・テストした。

## 未解決課題・申し送り事項

ユーザーが検証環境で実機確認し、問題なしと確認した（2026-11-02）。これによりクローズした。確認した項目は[計画](../plans/2026-11-02_フェーズ4ステップ2c-h_新規追加時のnヶ月分商品妥当性チェック.md)「確認方法」の各項目、特に次の点の確認が必要。
- 期中（差分1〜11）：按分月数＝差分のnヶ月分商品は通り、不一致のnヶ月分商品とフル年額商品は「確認」押下時に止まること（追加時点では警告が出ないこと）
- 更新タイミング（差分0）：2c-gの検証でブロックされず、フル年額商品は通り、nヶ月分商品は止まること
- 按分月数が空の商品が止まらないこと、差分が負の場合のブロック（2c-gの見直し分）
- ステップa〜d・2c-gの回帰確認

按分月数列（`fidAddedProductProratedMonths`）は最終的に非表示とする方針（コラボフロー側の設定変更、JSの実装には影響しない）。
