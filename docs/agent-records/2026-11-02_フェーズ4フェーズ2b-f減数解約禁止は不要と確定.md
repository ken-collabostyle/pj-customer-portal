# フェーズ4 フェーズ2b-f（nヶ月分商品の減数・解約禁止）は実装不要と確定

- 日付: 2026-11-02
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

[2b-eの記録](2026-10-26_フェーズ4フェーズ2b-e読み替え機能は不要と確定.md)の時点で、2b-f（期中に発注された「nヶ月分」商品の行は解約や減数ができないようにする制御）は業務支援チームに確認中だった。ユーザーが業務支援チームと会話し、結論を共有した。

## 確認結果（Reasoning）

ユーザーからの共有：

- 現在の要件にある「期中に発注された『nヶ月分』商品の行は、解約や減数ができないようにする制御を実装する」は**不要**。
- 理由：
  - 年額契約の場合、期中での解約、減数、プランダウンはできない。
  - 更新タイミングであれば、減数、プランダウン、年額→月額への変更、および解約（契約を更新しなければ、自動的にその商品は解約になる）が可能。

## 反映内容（Acting）

- [フェーズ4計画](../plans/2026-09-25_フェーズ4_年額契約変更カスタマイズ計画.md)：2b-fを不要として完了扱い、突合キー確認を不要に、`kintone-product-master`プロキシ作成を「2c-hの按分月数の取得方法次第」に更新、更新履歴に追記
- [年額版実装メモ](../forms/requirements/【クラウド版】注文書兼利用申込書（年額：契約変更）_実装メモ.md)：1.4-2を実装不要に、要確認事項7を不要に更新
- [2b-eの記録](2026-10-26_フェーズ4フェーズ2b-e読み替え機能は不要と確定.md)：未解決課題（2b-f確認待ち）を解消し、resolvedに更新

コード変更はなし。

## 得られた知見・製品への示唆

- 2b-e・2b-fとも、要求事項の記載（nヶ月分商品の読み替え・制限）は、実際の運用（nヶ月分商品も年額商品として登録され、期中の解約・減数自体が不可）では不要だった。実装前に業務支援チームに運用実態を確認することで、商品マスタ連携（突合キー・プロキシ・変換テーブル）の実装を避けられた。
- フェーズ2の残りは2c-hのみとなった。

## 未解決課題・申し送り事項

- 実装コード内のコメントに、2b-f不要の確定前の記述が残っている。
  - `src/forms/annual-contract-change.ts`のステップb解約連動のコメント（「nヶ月分商品の除外はフェーズ2で追加」等）
  - `src/forms/annual-contract-change-logic.ts`の`buildLineItems`のコメント（「nヶ月分商品の年間商品への読み替えは行わない（フェーズ2…）」）
  - コメントのみの修正でコード動作は変わらないが、実装作業にあたるため、承認を得てから修正する。
- 年額契約は期中での解約・減数ができない運用との関係：現在の年額版フォームは、解約チェックの連動（ステップb）と変更後契約数の入力を、変更適用希望年月に関わらず許容している。業務上、期中の変更適用希望（変更適用月差分が1以上）で解約・減数が入力された場合に制御が必要かどうかは未確認（今回の確認内容は「nヶ月分商品の制御は不要」であり、全商品に対する期中制限の要否は明示されていない）。必要であれば別途、業務支援チームに確認し、詳細計画を作成する。
- 2c-h（新規追加時の「nヶ月分」商品の妥当性チェック）は、新規追加商品の`按分月数`の取得方法の確定が前提。
