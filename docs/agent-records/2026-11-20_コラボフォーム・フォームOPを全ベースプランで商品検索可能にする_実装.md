# コラボフォーム・フォームOPを全ベースプランで商品検索可能にする（月額・年額）

- 日付: 2026-11-20
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

商品マスタの「コラボフォーム」「フォームOP」の商品は、「★スタンダード／プレミアム／エンタープライズ：表示」に「表示」が入っていないため、表示フラグで絞り込む商品検索には出てこない。すべてのベースプランで選択できるようにする。

## 調査内容（Reasoning）

- 検索条件は`buildProductSearchQuery`（[product-search-logic.ts](../../src/forms/product-search-logic.ts)）が組み立てる。月額・年額フォームで共用のため、1か所の変更で両方に反映される。
- 区別には商品マスタの商品区分2（`文字列__1行__5`、文字列1行）の値「フォーム」「フォームOP」を使う。文字列フィールドでもkintoneクエリの`in`による完全一致が使える。
- ユーザー確認（2026-11-20）：商品区分2に「フォーム」「フォームOP」が入っている。フォーム系商品には月額／年額・クラウドの値も入っている。販売終了フラグ・見積検索対象外は従来どおり適用する。
- ライト／プロプラン（契約DBの`種類２`、区分=フォーム）は、検索に使うプラン名の取得元（区分=ベースの行。`findBaseRecord`）に入らない。コラボフォームはコラボフロー（ベース契約）が前提のサービスのため、フラグに該当しないプランでの検索不可（案内表示）は現状維持とした（ユーザー確認済み）。

## 実施内容（Acting）

- `FORM_PRODUCT_CATEGORIES = ["フォーム", "フォームOP"]`を追加。
- 表示フラグ条件を`(<プランの表示フラグ> in ("表示") or 文字列__1行__5 in ("フォーム","フォームOP"))`に変更。月額年額・クラウド・販売終了・見積検索対象外の条件は変更なし。
- [product-search-logic.test.ts](../../tests/forms/product-search-logic.test.ts)の期待値を更新。

## 結果・観察（Observation）

- lint / typecheck / build通過。test 4ファイル137件通過。
- `npm test`の失敗原因が判明：シェルの作業ディレクトリのドライブレターが小文字（`c:\...`）だとvitestが二重ロードされ、`Cannot read properties of undefined (reading 'config')`で全ファイルが失敗する。`C:\...`（大文字）で実行すれば通常設定で通る（変更を退避した状態でも同じ失敗を確認）。前回記録の「原因未調査」を解消。
- 検証環境の実機確認（Playwright、コンソールエラーなし）：
  - 月額（プレミアムプラン）：ダイアログにFOKFLI0005M（ライト）・FOKFMP0500M／FOKFMP1000M（マイページオプション）・FOKFPR0000M（プロ）が表示される。「コラボフォーム」検索でFOKFST0020M（スタンダード）を含む5件。FOKFMP1000Mの選択で名称・商品コード・単価50000・区分「フォームOP」がセットされる。
  - 年額（スタンダードプラン）：「コラボフォーム」検索でFOKFLI0005M01〜、FOKFMP0500M01〜等が表示される。FOKFLI0005M01の選択で名称・コード・単価・区分「フォーム」・按分月数1がセットされる。
- 検証できていないプラン：エンタープライズ、アカガバ（スタンダード・プレミアムは確認）。

## 追加対応：並び順の降順化とページング（2026-11-20、ユーザー指示）

実機確認で、検索結果が20件で打ち切られ、空欄検索ではフォーム系商品が見えない（年額スタンダードで確認。月額でも空欄検索ではスタンダードプラン商品が20件目以降になる）ことが分かった。ユーザー指示により、次の2点を対応した。

- **並び順**：メーカー型番の降順（`order by 文字列__1行_ desc`）。空欄検索でもFOKF…（コラボフォーム）が先頭に来る。
- **ページング**：1ページ20件（`PRODUCT_SEARCH_PAGE_SIZE`）。kintoneの`limit 21 offset (page-1)*20`で1ページ分+1件を取得し、21件目の有無で次ページを判定する（総件数の取得は不要。プロキシで`totalCount`が通るか不明だったため）。ダイアログ下部に「前へ／n ページ目／次へ」を表示。再検索すると1ページ目に戻り、ページ移動中は検索ボタン押下時点のキーワードを使う。
- `splitProductSearchPage`を追加し、vitestでクエリ（`desc`・`offset`）とページ判定を確認（test 140件通過）。lint / typecheck / buildも通過。
- 実機確認（Playwright、コンソールエラーなし）：
  - 月額（プレミアム）：1ページ目はFOKFST0020M〜FOKFLI0005M（フォーム系5件）→CCUL…→CCTLST0000Mの20件。「次へ」で2ページ目（CCDCAD0010M、1件）、最終ページで「次へ」無効、「前へ」で戻り、再検索で1ページ目。
  - 年額（スタンダード）：空欄検索で全13ページ（最終ページ11件）。1ページ目の先頭はFOKFST0020Y。最終ページで「次へ」無効、「前へ」で戻り、再検索で1ページ目、行選択（FOKFST0020Y）で名称・コード・単価・区分「フォーム」・按分月数12がセットされる。
- 年額版の初回確認時は、年額版JSのアップロード漏れにより古い動作（昇順・ページングなし）だった。再アップロード後に確認した（ビルド成果物は正しかった）。

## 得られた知見・製品への示唆

- 年額は按分月数ごとの商品（1ヶ月〜11ヶ月・12ヶ月）があるため、空欄検索では13ページになる。商品名での検索が実質的な絞り込み手段。

## 未解決課題・申し送り事項

- エンタープライズ・アカガバのプランでの実機確認は未実施（クエリ組み立ては単体テストで確認済み）。
- 年額版の一覧は、同一商品の按分月数違いが連続して多数並ぶ。見づらければ、月数違いの並び順や表示の工夫を検討する余地がある（要件の相談が必要）。
- 本番の商品マスタでも、フォーム系商品に商品区分2・月額年額・クラウドが入っているかの確認が必要（[引き継ぎ事項#3](../handover/業務支援チーム引き継ぎ事項.md)に追記）。
