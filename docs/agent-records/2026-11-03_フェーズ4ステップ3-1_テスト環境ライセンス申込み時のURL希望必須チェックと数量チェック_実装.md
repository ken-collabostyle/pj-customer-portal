# フェーズ4 ステップ3-1 テスト環境ライセンス申込み時のURL希望必須チェックと数量チェック

- 日付: 2026-11-03
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

[フェーズ4計画](../plans/2026-09-25_フェーズ4_年額契約変更カスタマイズ計画.md)フェーズ3のうち、テスト環境ライセンス（★1）の条件付き必須。あわせて、確認の過程で「商品を選択して数量が未入力・0のまま申請を進めるのはおかしい」との指摘があり、全新規追加行の数量チェックを追加した。

## 調査内容（Reasoning）

[判別方法の確定](2026-11-02_フェーズ4フェーズ3テスト環境ライセンスの判別方法確定.md)（商品コードに`CCTLST0000`を含む）、★1の必須範囲（URL希望①〜③）、必須化の方式（確認・送信時のブロック）、数量チェックの対象範囲（商品が選択されたすべての新規追加行、1以上の整数）、既存契約は対象外、をユーザー確認のうえ、[詳細計画](../plans/2026-11-02_フェーズ4ステップ3-1_テスト環境ライセンス申込み時のURL希望必須チェック.md)でユーザー承認を得た。`fidAddedProductQuantity`は`required: false`のため、従来は商品を選んで数量が空でも申請できた。

## 実施内容（Acting）

`src/forms/annual-contract-change-logic.ts`
- `findInvalidAddedQuantities`：商品が選択されている行（商品コードまたは商品名が入力）のうち、数量が1以上の整数でない行を返す
- `hasTestEnvLicenseProduct`：商品コードに`CCTLST0000`を含むものがあるか
- `findEmptyTestEnvUrlFields`：未入力のURL希望の表示名を返す

`tests/forms/annual-contract-change-logic.test.ts`：上記3関数のテストを追加。

`src/forms/annual-contract-change.ts`
- `validateAddedProductQuantities`（数量チェック）、`validateTestEnvUrls`（URL希望必須チェック）を追加し、`form.confirm`/`form.submit`のチェーンに連結（2c-hの按分月数チェックの後。数量→URL希望の順）

## 結果・観察（Observation）

`npm run lint` / `npm run typecheck` / `npm test`（115件、ステップ3-1・3-2で新規45件）/ `npm run build`をすべて実行し通過を確認した。

## 得られた知見・製品への示唆

数量チェックは全新規追加行が対象のため、従来は価格0のまま申請できていた「商品選択済み・数量未入力」の申請が、今後ブロックされる。取りやめたい行は商品名（lookup）を解除して行を空にする必要がある。

## 未解決課題・申し送り事項

ユーザーが検証環境で実機確認し、問題なしと確認した（2026-11-05）。これによりクローズした。確認した項目は[計画](../plans/2026-11-02_フェーズ4ステップ3-1_テスト環境ライセンス申込み時のURL希望必須チェック.md)「確認方法」の各項目、特に次の点の確認が必要。
- 商品を選択して数量が未入力・0のまま「確認」を押すと、商品の種類を問わず警告が出ること。商品名（lookup）を解除して行を空にできること
- テスト環境ライセンス追加時、URL希望が1つでも未入力だと警告が出ること（未入力の項目名が出ること）
- テスト環境ライセンス以外の商品のみの場合、URL希望が空でも進めること
- ステップa〜d・2c-g・2c-h・ステップ3-2の回帰確認

(完了済み。)コラボフォーム（★2・★3）と同月内の減数不可は、判別方法・データソースが未確認のため別途。
