# フェーズ4 フェーズ2c 変更適用月差分の算出式確定

- 日付: 2026-10-26
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

`fidChangeApplyMonthDiff`（変更適用月差分）の算出式は、2026-09-25にユーザーが別途確認する方針としたため、フェーズ2c（g：自動計算・セット、h：新規追加時の「nヶ月分」商品妥当性チェック）を保留していた。ユーザーが業務支援チームに確認し、算出式を共有した。

## 確認結果（Reasoning）

ユーザーからの共有：

- 契約期限は必ず月末（クラウド契約管理DBの`契約終了日`の「月末」）。運用上、必ず月末になっている。
- 変更適用希望月が10月なら、課金されるのは11月から。
- 変更適用希望月の翌月からの残期間が、変更適用月差分。

これを年月の計算式にすると、`（契約期限の年×12＋月）－（変更適用希望年×12＋月）`になる（Claudeによる式化。業務支援チームの確認済みではないため、詳細計画でユーザーに確認する）。例：適用希望2026年10月・契約期限2027年3月末なら、課金対象は2026年11月〜2027年3月の5ヶ月で、差分は5。

## 反映内容（Acting）

- [フェーズ4計画](../plans/2026-09-25_フェーズ4_年額契約変更カスタマイズ計画.md)：フェーズ2cを「算出式確定済み」に更新し、確定ルールと未確認の論点を記載、更新履歴に追記
- [年額版実装メモ](../forms/requirements/【クラウド版】注文書兼利用申込書（年額：契約変更）_実装メモ.md)：1.3に確定した算出式を追記

コード変更はなし。

## 得られた知見・製品への示唆

- 契約期限が必ず月末という運用前提があるため、日付の日は考慮せず年月のみで計算できる。
- `fidChangeApplyMonthDiff`は`number_v2`の通常入力パーツのため、自動セットだけでは、ユーザーが手入力で書き換えられる。書き換え可否の方針を詳細計画で決める必要がある。

## 未解決課題・申し送り事項

- 2c-g・2c-hの詳細計画を作成し、承認を得る。以下の論点を詳細計画で確定する。
  - 差分が0以下（適用希望月が契約期限月以降）の場合の扱い
  - 差分が12以上になりうるか、その場合の扱い（「按分月数12＝フル年額」との関係）
  - 2c-hで新規追加商品の`按分月数`をどう取得するか。案として、`fidAddedProductName`のlookupに`按分月数`を新設パーツへ自動セットする設定を追加すれば、`kintone-product-master`プロキシが不要になる（`fidAddedProductCategory`と同じ方式）。ユーザー・業務支援チームでの確認が必要
  - `fidChangeApplyMonthDiff`のロック要否
  - 適用希望年月の変更時、およびインスタンス切り替え時（契約期限が変わる）の再計算タイミング
- 詳細計画の完了・実機確認後、本記録をresolvedに更新する。
