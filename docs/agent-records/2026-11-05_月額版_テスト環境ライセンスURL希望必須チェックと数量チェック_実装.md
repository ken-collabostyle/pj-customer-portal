# 月額版へのテスト環境ライセンスURL希望必須チェック（★1）・数量チェックの適用と共通化

- 日付: 2026-11-05
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

年額版のステップ3-1で実装・実機確認した、テスト環境ライセンス（商品コードに`CCTLST0000`を含む）追加時のURL希望①〜③必須チェック（★1）と、新規追加行の数量チェックを、月額版にも適用する。月額版のフェーズ1のd（保留中）のうち★1の分にあたる。あわせて、年額専用ファイルにあったフォーム非依存の汎用ロジックを共通モジュールへ移した。

## 調査内容（Reasoning）

月額版の要求事項の★1は年額版と同一の文言、パーツID（`fidTestEnvUrl*`・`fidAddedProduct*`）も同一であることをパーツ構造JSONで確認した。月額版では3パーツとも`required: false`、`fidAddedProductQuantity`も`required: false`で、同じ抜けがあった。ユーザー確認事項3件（月額版でも★1の必須範囲は同じ3項目、数量チェックも適用、共通モジュールへの移動を承認）に回答を得て、[詳細計画](../plans/2026-11-05_月額版_テスト環境ライセンスURL希望必須チェックと数量チェック.md)でユーザー承認を得た。

## 実施内容（Acting）

共通モジュールへの移動（動作変更なし）
- `src/forms/annual-contract-change-logic.ts`から`src/forms/contract-change-shared-logic.ts`へ、`TEST_ENV_LICENSE_PRODUCT_CODE_KEYWORD`・`isBlankValue`・`findInvalidAddedQuantities`（と関連型）・`hasTestEnvLicenseProduct`・`findEmptyTestEnvUrlFields`を移動
- テスト（上記3関数のdescribe）を`tests/forms/annual-contract-change-logic.test.ts`から`tests/forms/contract-change-shared-logic.test.ts`へ移動（内容・件数は変更なし）
- `src/forms/annual-contract-change.ts`のimport元を共通モジュールに変更

月額版への適用（`src/forms/monthly-contract-change.ts`）
- パーツIDの定数（`fidAddedProductCode`・`fidAddedProductName`・`fidTestEnvUrlFirstChoice`等3つ）を追加
- `validateAddedProductQuantities`（数量チェック）・`validateTestEnvUrls`（★1）を追加（年額版と同じ構成・同じ警告文言）
- `form.confirm`/`form.submit`のチェーンを、`blockSubmissionIfDataIssueDetected() && validateChangeApplyMonth(data) && validateAddedProductQuantities(data) && validateTestEnvUrls(data) && validateOptionUserCounts(data)`に変更

## 結果・観察（Observation）

`npm run lint` / `npm run typecheck` / `npm test`（115件。共通化の前後で件数は同じ）/ `npm run build`（`dist/forms/monthly-contract-change.js`・`annual-contract-change.js`再生成）をすべて実行し通過を確認した。

## 得られた知見・製品への示唆

年額版で先に実装した検証を、月額版に適用する段階で共通モジュールへ移す方針（フェーズ4計画のアーキテクチャ方針）により、月額版側は定数・検証関数の呼び出し・チェーンへの連結のみで済んだ。数量チェックにより、月額版でも、商品を選択して数量が未入力・0の新規追加行がある申請は、今後ブロックされる。

## 実機確認（2026-11-20、Playwright MCP、検証環境）

2026-11-19 18:09ビルドのJSが反映された検証環境で、月額版を確認した（送信はしていない）。

- 数量：商品を選択して数量が未入力のまま「確認」を押すと、「追加商品の追加商品契約数が未入力または0です」でブロックされる。
- ★1（URL希望必須）：テスト環境ライセンス（CCTLST0000M、区分「テスト環境」）を追加してURL希望が空だと、「未入力：①②③」でブロックされる。①だけ入力すると「②③」だけが列挙される。3つ入力すると通過する。
- テスト環境ライセンス以外（for kintone、区分「オプション」）のみ追加した場合は、URL希望が空でも通過する。
- 補足：2026-11-18の変更により、★1の判別は商品コード（`CCTLST0000`）ではなく区分「テスト環境」ベースになっている。2026-11-19時点（商品マスタの区分が空）は発動せず、商品マスタ更新後の2026-11-20に発動を確認した。
