# フェーズ4 フェーズ2b-e（nヶ月分商品の年間商品への読み替え）は実装不要と確定

- 日付: 2026-10-26
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

フェーズ2a（商品マスタ連携の準備）の整理の過程で、クラウド契約管理DBと商品マスタの突合キーの用途（既存契約行から商品マスタの`按分月数`を引いて「nヶ月分」商品かを判定し、2b-e：年間商品への読み替え、2b-f：減数・解約禁止に使う）を確認した。その上で、ユーザーが業務支援チームとMTGを行い、仕様を確認した。

## 確認結果（Reasoning）

ユーザーからの共有（業務支援チームMTGの結果）：

- **2b-e（年間商品への読み替え）**：既存契約にはレコード上「nヶ月分」の商品は存在しない。nヶ月分商品も全て年額商品として登録されるため、契約レコードからnヶ月分商品を推測することは事実上できない。年額商品として登録され、更新時は必ず年額商品となる運用を踏まえると、そもそも「年額商品への読み替え」自体が不要。**この読み替え機能は実装しなくてよい**。
- **2b-f（減数・解約禁止）**：業務支援チームに確認中。

## 反映内容（Acting）

- [フェーズ4計画](../plans/2026-09-25_フェーズ4_年額契約変更カスタマイズ計画.md)：2b-eを不要として完了扱い、変換テーブルの確認を解消扱い、突合キー確認と`kintone-product-master`作成を保留に変更、更新履歴に追記
- [年額版実装メモ](../forms/requirements/【クラウド版】注文書兼利用申込書（年額：契約変更）_実装メモ.md)：1.4-1を実装不要に、要確認事項5を解消、7を保留に更新

コード変更はなし。

## 得られた知見・製品への示唆

- 要求事項に「既存契約のnヶ月分商品を読み替える」とあったが、実データの運用（nヶ月分商品も年額商品として登録）とは前提が異なっていた。要求事項の記載と運用の実態を、実装前に業務支援チームに確認することで、不要な実装（変換テーブルの整備、商品マスタ連携）を避けられた。
- 要求事項の「nヶ月分」の扱いは、2c-h（新規追加時の妥当性チェック）では引き続き意味を持つ（新規追加商品は商品マスタのlookupで選択されるため、既存契約の突合とは独立）。

## 未解決課題・申し送り事項

- **2b-f（減数・解約禁止）の確認結果待ち**。既存契約にnヶ月分商品が存在しない前提だと、既存行への適用対象自体がない可能性があるが、業務支援チームの結論を待つ。
- 2b-fの結論に応じて、突合キー確認と`kintone-product-master`作成の要否を判断する（要なら再開、不要なら削除）。
- 同様に、2b-fの結論次第で、ステップbの「nヶ月分商品の除外は後で追加」というコメント・計画記載の見直しが必要になる可能性がある。
- 2c（g・h）：変更適用月差分の算出式は引き続き確定待ち。
- 2b-fの結論が出たら、本記録をresolvedに更新する。
