# フェーズ4 フェーズ3 同月内の減数不可はシステム的な制限を実装しないと確定

- 日付: 2026-11-05
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

要求事項「同月に別途ユーザー追加があった場合、同月内の減数は不可となる」（月額・年額共通）は、「別途ユーザー追加」をどのデータで判定するかが未確定のまま、月額版の時点から保留になっていた。ユーザーが業務支援チームに確認し、結論を共有した。

## 確認結果（Reasoning）

ユーザーからの共有：

- 本制限については、システム的な制限は実装しない。
- 同月内での申請があれば、受け付けたメンバーが目視で確認し、コラボフローの機能を使って差し戻しする運用を行う。

## 反映内容（Acting）

- [フェーズ4計画](../plans/2026-09-25_フェーズ4_年額契約変更カスタマイズ計画.md)：「同月内の減数不可チェック」を、実装しないと確定したものとして完了扱いにし、更新履歴に追記
- [年額版実装メモ](../forms/requirements/【クラウド版】注文書兼利用申込書（年額：契約変更）_実装メモ.md)・[月額版実装メモ](../forms/requirements/【クラウド版】注文書兼利用申込書（月額：契約変更）_実装メモ.md)：該当箇所に確定を追記

コード変更はなし。

## 得られた知見・製品への示唆

判定データソース（kintone側の履歴かコラボフロー側の申請履歴か）を整備せず、運用（受付メンバーの目視確認と差し戻し）で対応する判断となった。システム側の開発コストを避けられる一方、運用負荷は受付側に残る。

## 未解決課題・申し送り事項

なし。月額版・年額版のどちらも、同月内の減数不可はシステム的な制限を実装しない。フェーズ3の残りは、コラボフォーム（★2・★3）の条件付き必須とサブドメインのセットのみ。
