# 新規追加商品の単価は商品マスタのlookupで「標準売価」をセットすると確定

- 日付: 2026-11-18
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

月額版フォームの最新パーツ構造JSON（コラボフローAPIの`getFormParts`、form_id=36）を取得したところ、`fidAddedProductName`のlookupに「標準単価→`fidAddedProductUnitPrice`」の対応付けが追加されていた。2026-09-11にlookupから単価の自動セットが削除され、定価の取得元をライセンス種類マスタの`月額単価`とする方針にしていた（JS実装は未着手）ため、方針を確認した。

## 確認結果（Reasoning）

ユーザー回答（2026-11-18）：

- 新規追加商品の単価（定価）は、商品マスタからlookupで追加し、**kintone「標準売価」フィールド**を`fidAddedProductUnitPrice`にセットする（フィールドコードは`標準単価`、ラベルが「標準売価」）。
- 契約上特価で販売している場合もあるが、新規追加時は必ず定価とする運用で、イレギュラーは発生しない。特価が必要な場合は、営業的な個別対応（本システムを使わず従来どおり見積もりを提示）とする。
- ライセンス種類マスタの`月額単価`を使う計画は不要。
- 年額版にも同じlookup設定を追加した（再取得して確認済み）。
- 月額版の追加商品区分（`fidAddedProductCategory`）の非表示化は、意図したもの（ユーザーにあまり意味のない情報のため）。
- 年額版も、追加商品区分（`fidAddedProductCategory`）と追加商品按分月数（`fidAddedProductProratedMonths`）を非表示にした。いずれも意図したもの（再取得して`display: false`を確認済み）。

## 実施内容（Acting）

- 月額版・年額版のパーツ構造JSONを最新に更新（月額：規約合意系2パーツの削除、`fidAddedProductName`のlookupへの標準単価追加と`master_parts_key`・`master_id`の追加、追加商品区分の非表示化、`fidCollaboflowTermsAgreement`の`checked_comment`の小文字化。年額：lookupへの標準単価追加、追加商品区分と按分月数の非表示化）。
- 実装メモ（月額・年額）、kintone資料（商品マスタ・ライセンス種類マスタ・README）、全体計画に、確定内容を反映。

## 結果・観察（Observation）

- 年額版は、更新前のJSONと取得したJSONで、標準単価の追加と`master_parts_key`の変更のみの差異だった（`master_parts_key`はフォーム保存のたびに変わるとみられ、仕様ではない）。
- コード変更はなし。単価のJS実装は不要。

## 得られた知見・製品への示唆

- 単価は、フォーム側のlookup設定で完結するため、JSでの取得・セットは不要。商品マスタ側の「標準売価」の値が、そのまま申請内容の単価になる。
- 追加商品区分は、非表示でも、lookupによる値のセットは継続する。区分を使うチェック（ユーザー数整合性、★1）は、非表示でも動作する。

## 未解決課題・申し送り事項

- 年額版の追加商品区分と按分月数の非表示化は、意図したものと確認済み。非表示でもパーツの値は保持され、区分を使うチェック（ユーザー数整合性、★1）と按分月数のチェックは動作する。按分月数のエラーメッセージは商品名と「nヶ月分」で説明する形のため、非表示でも支障はない。コード変更は不要。
- `master_parts_key`は、フォームの保存で変わるため、JSON差分に出ても仕様変更ではない。
