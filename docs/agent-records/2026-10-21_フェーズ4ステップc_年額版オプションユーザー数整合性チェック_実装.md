# フェーズ4 ステップc 年額版オプションユーザー数整合性チェック

- 日付: 2026-10-21
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

[フェーズ4計画](../plans/2026-09-25_フェーズ4_年額契約変更カスタマイズ計画.md)フェーズ1のステップc。「オプションがユーザーライセンス形式の場合、オプションのライセンス数がベースライセンスと同じユーザー数になっているかをチェックする」要求を、年額版フォームに実装する。

## 調査内容（Reasoning）

月額版ステップeの実装資産を確認した。判定ロジック`findUserCountMismatches`は共通モジュール`contract-change-shared-logic.ts`へ切り出し済みでユニットテストも整備済み、年額版の`buildLineItems`も`category`を返し`currentLineItemCategories`に保持済み（ステップaで先行実装）、新規追加行の`fidAddedProductCategory`・`fidAddedProductQuantity`も月額と同一IDで存在することを確認。未実装なのは年額版側のバリデーション関数と`form.confirm`/`form.submit`への組み込みのみと判断し、[詳細計画](../plans/2026-10-21_フェーズ4ステップc_年額版オプションユーザー数整合性チェック.md)を提示、ユーザー承認を得た。

## 実施内容（Acting）

`src/forms/annual-contract-change.ts`に以下を追加（月額版`validateOptionUserCounts`と同じ構成）。

1. `findUserCountMismatches`のimport、定数`ADDED_PRODUCT_QUANTITY_PART_ID`・`ADDED_PRODUCT_CATEGORY_PART_ID`・`OPTION_USER_COUNT_MISMATCH_MESSAGE`
2. `validateOptionUserCounts(data)`：既存行（キャッシュ済み区分・変更後契約数・解約状態）と新規追加行（区分・追加商品契約数）を集めて判定し、不一致があれば`alert()`で警告して`false`を返す
3. `form.confirm`/`form.submit`を`blockSubmissionIfDataIssueDetected() && validateOptionUserCounts(data)`に変更
4. 関連コメントの更新（`currentLineItemCategories`の用途明記、計画への参照追加）

共通モジュール・純粋ロジック・テストファイルの変更はなし。

## 結果・観察（Observation）

`npm run lint` / `npm run typecheck` / `npm test`（70件、変更なし）/ `npm run build`（`dist/forms/annual-contract-change.js`再生成）をすべて実行し通過を確認した。

## 追記（2026-10-21）：解約ロック時の背景色の追加

ステップb回帰確認で、解約ON後のロックは維持されているが、見た目が変わらずロック中と分からないとの指摘があった。`setChangedQuantityFieldLocked`にロック時の背景色`rgb(241, 243, 245)`適用（アンロック時は解除）を追加し、ユーザー承認のうえ月額版にも同様に適用した（`monthly-contract-change.ts`、`annual-contract-change.ts`）。lint/typecheck/test（70件）/buildで確認済み。

## 得られた知見・製品への示唆

共通モジュール化（[共通モジュール抽出](../plans/2026-09-28_フェーズ4_共通モジュール抽出.md)）とステップaでのカテゴリ先行保持により、年額版ステップcは純粋なDOM／イベント側の追加のみで済んだ。

## 未解決課題・申し送り事項

なし。ユーザーが検証環境で[計画](../plans/2026-10-21_フェーズ4ステップc_年額版オプションユーザー数整合性チェック.md)「確認方法」の各項目（背景色追加分を含む）を実機確認し、正常動作を確認した（2026-10-21）。これによりクローズした。

なお、「nヶ月分」商品の扱いはフェーズ2で商品マスタ連携が解消した後に改めて検討する。
