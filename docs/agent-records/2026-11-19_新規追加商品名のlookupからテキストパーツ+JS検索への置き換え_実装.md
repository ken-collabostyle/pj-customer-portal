# 新規追加商品名のlookupからテキストパーツ＋JS検索への置き換え（月額・年額）

- 日付: 2026-11-19
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

lookupではベースライセンス別の絞り込み等の要件を満たせないため、`fidAddedProductName`をテキストパーツ＋虫眼鏡＋検索ダイアログ（プロキシAPI経由で商品マスタを検索）に置き換える。

## 調査内容（Reasoning）

- 検索条件：月額／年額（月額版=月額、年額版=年額。年額はユーザー指示）・クラウド・ベースライセンス別の表示フラグ・販売終了フラグ空・見積検索対象外空。
- 契約DBの実データで、プラン名（`種類２`）は「プレミアムプラン アカデミック/ガバメントライセンス」のようにアカガバ表記が付くものがあると判明。「アカデミック／ガバメント」を含む場合はアカガバ用フラグを優先する判定にした。
- lookupで自動セットしていた追加商品区分（ユーザー数整合性・★1が依存）と、年額の按分月数も、行選択時にJSでセットする（ユーザー確認済み）。

## 実施内容（Acting）

- [product-search-logic.ts](../../src/forms/product-search-logic.ts)（純粋関数＋テスト）、[product-search-dialog.ts](../../src/forms/product-search-dialog.ts)（虫眼鏡・ダイアログ）を新規作成し、月額・年額フォームに組み込み。
- コミット：35604c5, fbd4b99, cf37a5c, a6a6f19, 062bffb。
- 検証環境の実機確認（Playwright）：月額・年額とも、虫眼鏡表示、固定条件での一覧、プラン別絞り込み、行選択後のセット（商品コード・単価、年額は按分月数）を確認。コンソールエラーなし。

## 結果・観察（Observation）

- プロキシ設定の誤りが複数発生：①商品マスタ用に契約DBの設定（`app=73`＋`query`）を流用、②`app`未設定（`app: 必須です`）、③ヘッダー（APIトークン）未設定（`401 CB_AU01`）。
- 契約情報が取れない原因は、設定ではなくデータ（対象顧客が年額のみ、`インスタンス`が空）だった。
- `${user.customer_no}`（ユーザー拡張項目）はプロキシのクエリで解決された。
- `npm test`（通常設定）は、変更前の状態でも既存3ファイルが`Cannot read properties of undefined (reading 'config')`で失敗する。`--pool=vmThreads`では全137件が通る（環境起因。原因未調査）。

## 得られた知見・製品への示唆

- プロキシAPIは、ドキュメント上はワークスペース共有だが、実機ではフォーム単位（月額・年額で別名が必要）。
- プロキシのクエリパラメーターは管理者設定が優先され、JSの`query`で上書きできない。検索条件をJSから渡す用途では、管理者側に`query`を設定しないこと。

## 再確認（2026-11-20、Playwright MCP、検証環境）

商品マスタ（検証用）の「商品名_マイページ用」「商品区分2」の更新後に再確認した。コンソールエラーなし。

- 月額：ダイアログに商品名が表示される。名称検索（「テスト」）でCCTLST0000Mの1件に絞り込める。行選択で名称・商品コード・単価・区分がセットされる（テスト環境ライセンスは区分「テスト環境」、for kintoneは「オプション」で単価50×10=500）。
- 年額：商品名が「年額 5ヶ月」のように表示され、CCDCAD0010M05の選択で名称・単価・区分「オプション」・按分月数5がセットされる。
- 副次的に、月額版のテスト環境ライセンスURL希望必須チェック（区分「テスト環境」で発動、未入力の項目名を列挙、全入力で通過、他商品のみなら不要）も確認した（[月額版の記録](2026-11-05_月額版_テスト環境ライセンスURL希望必須チェックと数量チェック_実装.md)参照）。
