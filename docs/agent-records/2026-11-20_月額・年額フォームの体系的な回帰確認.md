# 月額・年額フォームの体系的な回帰確認

- 日付: 2026-11-20
- 担当: 波多野（開発窓口） / Claude Code

## 背景・目的

共通モジュール化（2026-11-05）、テスト環境ライセンス判別の区分ベース化（2026-11-18）、商品検索への置き換え（2026-11-19）を経て、月額のステップa〜b・e・f、年額の2c-g・3-2・2c-hの個別の回帰確認が未実施だったため、検証環境で体系的に確認した。実装は伴わない（コード変更なし）。

## 方法（Acting）

## 得られた知見・製品への示唆

- 変更後契約数のロック（解約連動）は、読み取り専用が即時、値の0への変更が約0.3〜1秒後に反映される。利用上の問題はないが、自動操作で確認する場合は待ち時間が必要。
- Playwrightの`fill`で入力するとフォームの内部状態が更新されない場合がある（価格が再計算されず、確認ボタンが無効のままになる）。実際のキー入力（`type`・`press`）を使う。
- 一度「確認」がJSの検証でブロックされると、確認ボタンが無効のままになる場面があった（変更後に有効に戻る）。コラボフォーム側の挙動とみられ、実害は未確認。
- 月のプルダウンには「--- 未選択 ---」があり、月を空にできる（2026-11-05の記録では「UI上は空にできない」と判断していたが、誤り）。

  - 当月選択可能期限の年またぎ（12月→翌年1月）、祝日を含む営業日計算の公式発表との照合。
