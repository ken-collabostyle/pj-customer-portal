# フェーズ4 ステップ2c-h 詳細計画：新規追加時の「nヶ月分」商品妥当性チェック

[フェーズ4計画](2026-09-25_フェーズ4_年額契約変更カスタマイズ計画.md)フェーズ2cのステップh。CLAUDE.md「1. 推論」の承認ゲートルールに基づき、実装着手前に本計画をユーザーの承認を得てから着手する。

## 承認状況

承認済み（2026-11-02、2c-gの検証見直し（差分0を許可）を含む）

## 要求事項（該当箇所抜粋）

> * 「nヶ月分」の商品が追加された場合は、変更適用月差分と現在契約期限を元に、正しい商品が選択されているかをチェックし、不正な商品の場合は申請できないようにする。（要求事項28行目）
> * 「nヶ月分」の商品は「n」毎に商品コードが異なる。（同29行目）
> * 「nヶ月分」の商品かどうかはkintoneの商品マスタ「label=按分月数」で確認できる。「按分月数」が12のものはフルの年額、それより低い値のものは、nヶ月分商品である。（同30行目）

## ユーザー確認済みの方針（2026-11-02）

| 論点 | 回答 |
| --- | --- |
| 按分月数の意味 | 按分月数5の商品は「5ヶ月分」を指す |
| フル年額商品（按分月数12）の期中追加 | **不正**。追加した時点ではなく、入力後に「確認」ボタンを押した際に警告を出して申請を止める |
| 更新タイミングの差分 | **許される**（2c-gの「差分0以下は申請不可」との関係は下記「2c-gの検証の見直し」参照） |
| 按分月数列の表示 | 最終的には非表示とするが、一旦は現状（`display: true`）のままとする |
| 更新タイミング | **差分0**（変更適用希望月＝契約期限の月）でよい（別運用ではない） |
| 差分0のとき追加できる商品 | フル年額商品（按分月数12）のみ。nヶ月分商品は不可 |
| 差分12以上 | **運用上起こりえない**。防御的に、差分0と同じ扱い（フル年額商品のみ）とする |
| 按分月数が空の商品 | チェック対象外とする |

## 事前調査の結果（Reasoning）

| 項目 | 状態 |
| --- | --- |
| 新規追加商品の按分月数 | 2026-11-02にコラボフロー側で`fidAddedProductProratedMonths`（追加商品按分月数、`number_v2`）を追加。`fidAddedProductName`のlookup（`数値`→`fidAddedProductProratedMonths`）でセットされることをユーザーが実機確認済み（更新後の[パーツ構造JSON](../forms/json/【クラウド版】注文書兼利用申込書（年額：契約変更）.json)で反映を確認）。`kintone-product-master`プロキシは不要 |
| 変更適用月差分 | 2c-gで`computeChangeApplyMonthDiff`（`annual-contract-change-logic.ts`）を実装・実機確認済み。差分は契約期限（キャッシュ）と適用希望年月から都度算出できる。検証時もパーツ値は読まず再算出する |
| 検証のタイミング | `form.confirm`/`form.submit`のチェーンに連結する（ステップc・d・2c-gと同じ方式）。追加時点（`change`イベント）ではチェックしない（ユーザー回答のとおり） |
| 追加行の対象 | 新規追加側は`fidAddedProductName`/`fidAddedProductCode`/`fidAddedProductQuantity`/`fidAddedProductProratedMonths`が同一行に同居する（明細テーブル`tbl_1`）。ステップcの`validateOptionUserCounts`と同じく全行を走査する |

## 検証ルール（提案。確認事項あり）

「期中」「更新タイミング」を変更適用月差分（以下「差分」）で次のように読み替える（2026-11-02ユーザー確認済み）。

| 差分 | 意味 | 追加できる商品（按分月数） |
| --- | --- | --- |
| 1〜11 | 期中の追加 | 按分月数＝差分のnヶ月分商品のみ（例：差分5なら按分月数5） |
| 0 | 更新タイミング（変更適用希望月が契約期限の月。課金は翌月から更新後契約） | フル年額商品（按分月数12）のみ |
| 12以上 | 運用上起こりえない（防御的に差分0と同じ扱い） | フル年額商品（按分月数12）のみ |
| 負 | 契約期限より後の月を選択 | 本チェックはスキップ（2c-gの検証でブロック） |

- 対象行：商品が選択されており（`fidAddedProductCode`が空でない）、**按分月数が数値として入力されている行**
- 不一致の行が1つでもあれば、`form.confirm`/`form.submit`で`alert()`＋申請ブロック
- **按分月数が空・数値でない行**（月額商品など按分月数が未設定の商品が存在しうる）：チェック対象外（2026-11-02ユーザー確認済み）
- 警告文言案
  - 期中でフル年額商品を追加：「追加商品『○○』はフル年額の商品のため、期中（変更適用月差分△ヶ月）には追加できません。△ヶ月分の商品を選択してください。」
  - nヶ月分商品の按分月数が差分と不一致：「追加商品『○○』は○ヶ月分の商品です。変更適用月差分（△ヶ月）と一致するヶ月数の商品を選択してください。」
  - 更新タイミングでnヶ月分商品を追加：「追加商品『○○』は○ヶ月分の商品のため、更新タイミング（変更適用月差分0ヶ月）には追加できません。フル年額の商品を選択してください。」

### 「現在契約期限」の扱い
要求事項は「変更適用月差分と現在契約期限を元に」としているが、差分自体が契約期限と変更適用希望年月から算出された値（2c-g）であるため、契約期限は差分に織り込まれており、本チェックで別途参照する必要はない。

## 2c-gの検証の見直し（要承認）

2c-gでは「差分0以下は補正せず申請不可」とした（2026-10-26ユーザー確認済み）。今回「更新タイミングの差分は許される」との回答を受け、更新タイミングは**差分0**（変更適用希望月＝契約期限の月）と解釈し、この解釈が正しいことをユーザーが確認した（2026-11-02）。そのため、2c-gの`validateChangeApplyMonthDiff`を次のように見直す。

- 差分0：**申請可**（更新タイミング）
- 差分が負：申請不可のまま（契約期限より後の月は選択できない）
- 警告文言を「変更適用月差分が0未満になるため申請できません。変更適用希望年月が現在契約期限の月以前になるよう選択してください。」へ変更

変更は`annual-contract-change.ts`の`validateChangeApplyMonthDiff`（判定を`diff > 0`から`diff >= 0`へ）と文言のみ。純粋関数`computeChangeApplyMonthDiff`・テストの変更は不要。実機確認済みの2c-gに手を入れることになるため、本計画の承認時に合わせて承認を得る。

## 実装方針

### 1. `src/forms/annual-contract-change-logic.ts`（純粋ロジック、ユニットテスト対象）
- 新規インターフェース`AddedLineItemForProratedMonthsValidation`：`productCode: string`、`productName: string`、`proratedMonths: unknown`
- 新規型`ProratedMonthsMismatch`：行番号（1始まり）・商品名・按分月数・種別（`fullYearOnMidTerm`／`monthsMismatch`／`partialOnRenewal`）
- 新規関数`findProratedMonthsMismatches(addedRows, changeApplyMonthDiff: number)`：上記「検証ルール」に従い、不一致の行を返す
- 按分月数の数値化：空文字・空白のみ・`NaN`・負数・小数・13以上は対象外（異常値として検証に使わない）

### 2. `tests/forms/annual-contract-change-logic.test.ts`（テスト追加）
- 期中（差分1〜11）：按分月数＝差分 → 不一致なし／按分月数≠差分 → `monthsMismatch`／按分月数12 → `fullYearOnMidTerm`
- 更新タイミング（差分0）：按分月数12 → 不一致なし／nヶ月分 → `partialOnRenewal`
- 差分12以上：按分月数12 → 不一致なし／nヶ月分 → 不一致
- 差分が負 → 検証しない（空配列）
- 按分月数が空・NaN・負数・小数 → 対象外／商品未選択行 → 対象外
- 複数行が混在する場合に不一致行のみ返す／値が文字列・数値のどちらでも同じ結果になる（`parts.value`の型が未確認のため）

### 3. `src/forms/annual-contract-change.ts`
- 定数`ADDED_PRODUCT_CODE_PART_ID`・`ADDED_PRODUCT_NAME_PART_ID`・`ADDED_PRODUCT_PRORATED_MONTHS_PART_ID`（`"fidAddedProductProratedMonths"`）と警告文言を追加
- 関数`validateAddedProductProratedMonths(data)`：明細テーブル各行から値を集め、差分（`computeChangeApplyMonthDiff`で再算出、`null`ならスキップ）とともに`findProratedMonthsMismatches`へ渡す。不一致があれば最初の1件の種別に応じた文言で`alert()`＋`false`
- `validateChangeApplyMonthDiff`を「差分0は許可、負のみブロック」へ見直し（上記「2c-gの検証の見直し」）
- `form.confirm`/`form.submit`のチェーンに連結：`blockSubmissionIfDataIssueDetected() && validateChangeApplyMonth(data) && validateChangeApplyMonthDiff(data) && validateAddedProductProratedMonths(data) && validateOptionUserCounts(data)`
- ファイル先頭コメントに本ステップの参照を追記
