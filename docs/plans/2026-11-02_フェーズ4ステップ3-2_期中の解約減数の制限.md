## 背景・要件

2026-11-02の業務支援チームの確認（[2b-fの記録](../agent-records/2026-11-02_フェーズ4フェーズ2b-f減数解約禁止は不要と確定.md)）で、次の運用が分かった。

- 年額契約の場合、期中での解約、減数、プランダウンはできない。
- 更新タイミングであれば、減数、プランダウン、年額→月額への変更、および解約（契約を更新しなければ自動的にその商品は解約になる）が可能。

現在の年額版フォームは、変更適用希望年月に関わらず、全商品で解約・減数・増数を許容している。これに対し、**「年額は期中の解約・減数ができないように制御する」とユーザーが決定した（2026-11-02）**。あわせて、**期中のフル年額商品の増数もNG**と確認された。

## ユーザー確認済みの方針（2026-11-02）

| 論点 | 回答 |
| --- | --- |
| 期中の定義 | 変更適用月差分（以下「差分」）が1以上を期中、差分0を更新タイミングとする |
| 既存行の増数 | フル年額商品の増数はNG（期中の増数も制限する） |
| 警告のタイミング | 確認・送信時のみ（解約チェックON時や減数入力時の即時警告は不要） |
| 差分12以上 | 「何かおかしいことが起こっている」ため、警告を出して申請できなくする |

## 「期中」の定義

| 差分 | 意味 | 既存行の解約・減数・増数 |
| --- | --- | --- |
| 1〜11 | 期中（変更適用希望月が契約期限の月より前） | **不可**（本ステップで制限） |
| 0 | 更新タイミング（変更適用希望月＝契約期限の月） | 可 |
| 12以上 | 想定外（運用上起こりえない） | **警告して申請不可**（本ステップで追加） |
| 負 | 契約期限より後の月 | 2c-gの検証でブロック済み（本ステップでは扱わない） |
| 算出不能 | 契約期限が取得できない等 | 別のフェイルセーフでブロック済み（本ステップでは扱わない） |

プランダウン（解約＋新規追加による下位プランへの変更）と年額→月額への変更は、年額商品の解約を伴うため、解約の制限でカバーされる。

## 事前調査の結果（Reasoning）

| 項目 | 状態 |
| --- | --- |
| 解約・減数・増数の実現手段 | 解約は`fidProductCancel`（チェックボックス、`"解約"`/`"継続"`）。ONにすると変更後契約数が0固定になる（ステップb）。減数・増数は、`fidChangedProductQuantity`（変更後契約数）と`fidCurrentProductQuantity`（現商品契約数）の大小で判定する |
| UIでの制御可否 | 解約チェックボックスの無効化は、JS APIの`parts.enabled`が取得のみ（設定不可）のため、DOM操作が必要になり脆弱。他ステップと同じく`form.confirm`/`form.submit`でのブロック方式を採用する |
| 変更適用月差分の再算出 | 2c-g・2c-hと同様に、パーツ値は読まず`computeChangeApplyMonthDiff`で再算出する |
| 既存行の判別 | `fidCurrentProductQuantity`が入力されている行を既存契約行とみなす（`applyLineItemsToTable`が既存行にだけセットする。新規追加のみの行は空） |
| 2c-hとの関係 | 2c-hは期中の新規追加をnヶ月分商品のみ許可とした。既存のフル年額商品の増数を許可すると、フル年額商品を期中に増やすことになり趣旨と整合しないため、増数も制限する（ユーザー確認済み） |
| 差分12以上の扱い | 2c-hでは差分12以上を防御的に差分0と同じ扱い（フル年額のみ許可）としていたが、本ステップで差分12以上を警告して申請不可にするため、2c-hの当該分岐は事実上到達しない（防御的なコードとして残す。動作変更なし） |

## 検証ルール

### A. 期中（差分1〜11）の既存契約行の変更制限
期中の場合、既存契約行のうち次のいずれかに該当する行があれば、`alert()`＋申請ブロックする。

1. **解約**：`fidProductCancel`が`"解約"`（チェックON）
2. **減数**：変更後契約数が現商品契約数より小さい
3. **増数**：変更後契約数が現商品契約数より大きい

つまり、期中は既存契約行を現状のまま（変更後契約数＝現商品契約数、継続）にする必要がある（変更できるのは新規追加行のみ）。

- 変更後契約数が空・数値でない場合は、減数・増数の判定対象外（解約は`isCancelled`で判定）
- 警告文言案：「年額契約は期中の解約・減数・増数はできません。更新タイミング（変更適用希望年月を現在契約期限の月に設定）で申請してください。（対象：『○○』の解約）」（最初に見つかった1行を表示。解約・減数・増数で括弧内を出し分け）
- 差分0（更新タイミング）は制限なし

### B. 差分12以上の想定外チェック
差分が12以上の場合は、警告して申請ブロックする（想定外の状態のため）。
- 文言案：「変更適用月差分が12ヶ月以上になっています。想定外の状態のため申請できません。お手数ですがシステム管理者にお問い合わせください。」
- 実装は2c-gの`validateChangeApplyMonthDiff`に組み込む（差分が負の場合のブロックに加えて、12以上もブロック）

## 実装方針

### 1. `src/forms/annual-contract-change-logic.ts`（純粋ロジック、ユニットテスト対象）
- 関数`findMidTermChanges(existingRows: { productName: unknown; currentQuantity: unknown; changedQuantity: unknown; isCancelled: boolean }[], changeApplyMonthDiff: number)`
  - 差分が1未満、または12以上の場合は空配列（0は更新タイミング、12以上はBで別途ブロック）
  - 既存行（現商品契約数が空・空白でない）のうち、`isCancelled`が真の行は`kind: "cancel"`、そうでなく変更後契約数が現商品契約数より小さければ`"reduce"`、大きければ`"increase"`として、行番号（1始まり）・商品名とともに返す
  - 数値化できない値（空・数値でない）の行は、減数・増数の判定対象外（解約は`isCancelled`で判定）

### 2. `tests/forms/annual-contract-change-logic.test.ts`（テスト追加）
- 期中（差分1〜11）：解約ON→`cancel`／減数→`reduce`／増数→`increase`／同数・継続→対象外
- 更新タイミング（差分0）→空配列／差分12以上→空配列／差分が負→空配列
- 新規追加のみの行（現商品契約数が空）は対象外／数値でない値は減数・増数の判定対象外
- 複数行が混在する場合に該当行のみ返す（行番号つき）／文字列・数値のどちらでも同じ結果

### 3. `src/forms/annual-contract-change.ts`
- 関数`validateMidTermChanges(data)`：明細テーブル各行から商品名・現商品契約数・変更後契約数・解約状態を集め、差分（`computeChangeApplyMonthDiff`で再算出、`null`ならスキップ）とともに`findMidTermChanges`へ渡す。該当があれば最初の1件を、種別に応じた文言で`alert()`＋`false`
- `validateChangeApplyMonthDiff`（2c-g）に、差分12以上のブロック（B）を追加。文言用の定数を追加し、既存の負のブロックの文言・動作は変えない
- `form.confirm`/`form.submit`のチェーンに`validateMidTermChanges`を連結（`validateChangeApplyMonthDiff`の後、`validateAddedProductProratedMonths`の前）
- ファイル先頭コメントに本ステップの参照を追記

## 今回やらないこと（切り出し）

- 解約チェックボックスの無効化・入力欄のロック（DOM依存で脆弱なため、ブロック方式を採用）
- 解約チェックON時・減数入力時の即時警告（ユーザー確認済み：確認・送信時のみ）
- 同月内の減数不可（判定データソース未確認のため別扱い）
- 月額版への適用（月額は期中でも変更できる運用か未確認）

## 影響範囲

- 変更は`annual-contract-change-logic.ts`・`annual-contract-change.ts`・テストファイルのみ。月額版・共通モジュールへの影響なし
- **既存の運用への影響が大きい**：変更適用希望年月のデフォルトは当月（または翌月）で、通常は期中（差分1以上）になる。そのため、既存契約行の解約・減数・増数を含む申請は、変更適用希望年月を契約期限の月に変更しない限り、申請できなくなる
- 2c-g（`validateChangeApplyMonthDiff`）の動作が変わる：差分12以上を新たにブロックする（負のブロック・差分0の許可は変えない）
- ステップb（解約連動・ロック）の動作は変えない。期中でも解約チェックをONにできるが、確認・送信時にブロックされる

1. Claudeが`npm run lint` / `npm run typecheck` / `npm test` / `npm run build`を実行。純粋関数はユニットテストで網羅
2. ユーザーが検証環境（年額版フォーム）で以下を確認

   - 期中：既存行の変更後契約数を現契約数より減らして「確認」を押すと、警告が出て進めないこと
   - 期中：既存行の変更後契約数を現契約数より増やして「確認」を押すと、警告が出て進めないこと
   - 期中：既存行を変更せず、新規追加のみ（nヶ月分商品）の場合は進めること
