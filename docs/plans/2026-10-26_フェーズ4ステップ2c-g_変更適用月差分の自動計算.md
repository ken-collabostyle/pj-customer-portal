# フェーズ4 ステップ2c-g 詳細計画：変更適用月差分（fidChangeApplyMonthDiff）の自動計算

[フェーズ4計画](2026-09-25_フェーズ4_年額契約変更カスタマイズ計画.md)フェーズ2cのステップg。CLAUDE.md「1. 推論」の承認ゲートルールに基づき、実装着手前に本計画をユーザーの承認を得てから着手する。2c-h（新規追加時の「nヶ月分」商品妥当性チェック）は`按分月数`の取得方法が未確定のため、本計画の対象外とする。

## 承認状況

## 要求事項と確定した算出式

> 「nヶ月分」の商品が追加された場合は、変更適用月差分と現在契約期限を元に、正しい商品が選択されているかをチェックし…（要求事項28行目）

`fidChangeApplyMonthDiff`（変更適用月差分）の算出式は、2026-10-26の業務支援チームMTGで確定した（[実施記録](../agent-records/2026-10-26_フェーズ4フェーズ2c変更適用月差分の算出式確定.md)）。

- 契約期限（クラウド契約管理DBの`契約終了日`）は運用上必ず月末
- 変更適用希望月が10月なら、課金は11月から
- **変更適用月差分＝変更適用希望月の翌月から契約期限までの残月数**

年月での式（Claudeによる式化）：`（契約期限の年×12＋月）－（変更適用希望年×12＋月）`
例：適用希望2026年10月・契約期限2027年3月末 → 課金対象は11〜3月＝**5**。契約期限が月末のため、日は計算に使わず年月のみで足りる。

## ユーザー確認済みの方針（2026-10-26）

| 論点 | 回答 |
| --- | --- |
| 差分が0以下の場合 | 補正せず算出値（0や負の値）をそのままセットする。**ただし申請は不可とする** |
| 手入力の扱い | **readOnly化する**（ロックする） |
| 契約期限が取得できない場合（テスト環境ライセンス専用インスタンス等） | **警告を出して申請できないものとする** |

| 項目 | 状態 |

| `fidChangeApplyMonthDiff` | `number_v2`（`calculate`ではない通常入力パーツ）、`required: true`、小数なし（[パーツJSON](../forms/json/【クラウド版】注文書兼利用申込書（年額：契約変更）.json)） |

## 設計方針

### 1. 契約期限の取得元：`fidCurrentContractExpiry`のパーツ値は読まず、JS側のキャッシュを使う
日付パーツの値形式（表示形式`yyyy/m/d`）がkintoneの`YYYY-MM-DD`と一致する保証がなく、実機で確認しないと分からない。そこで、`applyInstanceData`でセットする際に使う値（`summary.contractExpiry`、形式が確定している）をモジュールレベルの変数`currentContractExpiry`に保持し、計算にはそれを使う。ベース行が見つからない場合・インスタンス切り替え時は空文字にリセットする。

### 2. 再計算のタイミング
| タイミング | 理由 |
| --- | --- |
| `applyInstanceData`の末尾 | 初期表示（kintone取得完了後）とインスタンス切り替えで契約期限が確定・変更されるため。この時点で`form.show`で設定済みのデフォルト年月を使って計算される |
| `form.fidChangeApplyYear.change` | 適用希望年の変更 |
| `form.fidChangeApplyMonth.change` | 適用希望月の変更 |

### 3. 計算不能な場合
適用希望年月が数値でない等で計算できない場合は、`fidChangeApplyMonthDiff`を空文字にする（誤った値を残さないため。年月の必須チェックはフォーム標準機能に委ねる）。

### 4. 差分が0以下の場合：値はそのままセットし、申請をブロックする
算出値（0や負の値）を補正せずセットする。`form.confirm`/`form.submit`で、算出値が0以下なら`alert()`＋`return false`で申請をブロックする（`validateChangeApplyMonthDiff`）。0は「適用希望月が契約期限月と同じ＝課金対象月なし」、負の値は契約期限より後の月を選んだ場合。

### 5. 契約期限が取得できない場合：警告して申請不可
`applyInstanceData`でベース行（`summary`）は取得できたが`contractExpiry`が空・形式不正の場合に、フラグ`contractExpiryMissing`を立てて`alert()`で警告する。`blockSubmissionIfDataIssueDetected`にも組み込み、`form.confirm`/`form.submit`でブロックする（既存の`baseRecordMissing`等と同じフェイルセーフ）。インスタンス切り替えで契約期限が取得できるインスタンスに戻った場合は`false`にリセットする。ベース行自体が見つからない場合は既存の`baseRecordMissing`で警告・ブロックされるため、二重に警告しない。

### 6. readOnly化（DOM操作）
`document.getElementById("fidChangeApplyMonthDiff")`で取得したネイティブinputを`readOnly`にする。インスタンス名入力欄と同じ取得方法を踏襲するが、`fidChangeApplyMonthDiff`の実DOMのID・構造は未確認のため、実機で確認する。
- 値のセット後に毎回ロックを適用する（`updateChangeApplyMonthDiff`内）
- ステップbと同様に、値セットで再描画され`readOnly`が外れる可能性に備え、`form.fidChangeApplyMonthDiff.change`でも再ロックする（ロックは値を変更しないため、再帰ループにならない）
- DOM取得に失敗した場合は、フラグ`changeApplyMonthDiffLockFailed`を立てて`alert()`で警告し、`form.confirm`/`form.submit`でブロックする（`cancelQuantityLockFailed`と同じフェイルセーフ）
- 見た目でロックと分かるよう、ステップbの解約ロックと同じ背景色`rgb(241, 243, 245)`を適用する（`LOCKED_FIELD_BACKGROUND_COLOR`を再利用。不要なら外す）

readOnly化により手入力できないため、「入力値が算出値と一致するか」の検証は設けない。

## 実装方針

### 1. `src/forms/annual-contract-change-logic.ts`（純粋ロジック、ユニットテスト対象）
- 新規関数`computeChangeApplyMonthDiff(applyYear: number, applyMonth: number, contractExpiry: string): number | null`
  - `contractExpiry`を`YYYY-MM-DD`として解釈し年・月を取り出す。形式不正・空なら`null`
  - `applyYear`・`applyMonth`が整数でない（`NaN`等）、または月が1〜12の範囲外なら`null`
  - それ以外は`（契約期限の年×12＋月）－（applyYear×12＋applyMonth）`を返す
- 月額・共通モジュールには置かない（年額専用ロジックのため、フェーズ4計画のアーキテクチャ方針どおり）

### 2. `tests/forms/annual-contract-change-logic.test.ts`（テスト追加）
- 基本例：適用2026年10月・契約期限2027-03-31 → 5
- 年またぎ：適用2026年12月・契約期限2027-03-31 → 3
- 同年内：適用2026年10月・契約期限2026-12-31 → 2
- 契約期限月と同じ月：適用2027年3月・契約期限2027-03-31 → 0
- 契約期限月より後：適用2027年4月・契約期限2027-03-31 → -1
- 12ヶ月：適用2026年10月・契約期限2027-10-31 → 12
- 契約期限が空・形式不正 → `null`
- 適用年月が`NaN`・月が範囲外 → `null`

### 3. `src/forms/annual-contract-change.ts`
- 定数を追加：`CHANGE_APPLY_MONTH_DIFF_PART_ID = "fidChangeApplyMonthDiff"`、警告文言3種（契約期限取得不可、ロック失敗、差分0以下で申請不可）
- モジュール変数を追加：`currentContractExpiry`、`contractExpiryMissing`、`changeApplyMonthDiffLockFailed`
- `applyInstanceData`：`currentContractExpiry`の更新、契約期限が取得できない場合の`contractExpiryMissing`設定・警告、末尾での`updateChangeApplyMonthDiff(data)`呼び出し
- 関数`updateChangeApplyMonthDiff(data)`：年月を数値化して`computeChangeApplyMonthDiff`を呼び、結果（または空文字）を`fidChangeApplyMonthDiff`にセットし、ロックを適用
- 関数`lockChangeApplyMonthDiffField()`：ネイティブinputを`readOnly`化し背景色を適用。失敗時は上記フラグを立てる
- イベントハンドラー：`form.fidChangeApplyYear.change`・`form.fidChangeApplyMonth.change`（再計算）、`form.fidChangeApplyMonthDiff.change`（再ロック）
- 関数`validateChangeApplyMonthDiff(data)`：算出値が0以下なら`alert()`＋`false`
- `blockSubmissionIfDataIssueDetected`に`contractExpiryMissing`・`changeApplyMonthDiffLockFailed`を追加し、`form.confirm`/`form.submit`のチェーンを`blockSubmissionIfDataIssueDetected() && validateChangeApplyMonth(data) && validateChangeApplyMonthDiff(data) && validateOptionUserCounts(data)`に変更
- ファイル先頭コメントに本ステップの参照を追記
